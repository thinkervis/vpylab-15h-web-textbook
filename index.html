실습 코드 3: 사라지는 구조대 공
from vpython import *

scene_background(color.cyan)
box(pos=vector(0, -0.1, 0), size=vector(8, 0.2, 5), color=color.green)

모듈 3. 클릭·키보드·소리를 순서대로 연결하기

7차시

1단계: 클릭을 먼저 “감지”하기

목표: 마우스 클릭이 작품 안에서 하나의 사건이 된다는 것을 확인한다. 아직 공을 움직이거나 소리를 넣지 않고, 클릭하면 표시 공만 옮겨본다.

scene.mouse.clickedscene.mouse.getclickevent

실습 코드 6-1: 클릭한 곳에 표시하기
from vpython import *

scene_background(color.cyan)
label(pos=vector(0, 2.8, 0), text="정원을 클릭해 보세요", height=12, color=color.black)
box(pos=vector(0, -0.1, 0), size=vector(8, 0.2, 5), color=color.green)

marker = sphere(pos=vector(0, 0.15, 0), radius=0.14, color=color.red)

while True:
    rate(60)

    if scene.mouse.clicked:
        click = scene.mouse.getclick()
        marker.pos.x = click.pos.x
        marker.pos.z = click.pos.z
클릭 코드 읽기: scene.mouse.clicked는 처리할 클릭이 있는지 확인하고, scene.mouse.getclick()은 그 클릭 이벤트 하나를 꺼내 사용합니다. 그래서 “확인한 뒤 꺼내기” 순서로 씁니다.

생각해보기

자동으로 움직이는 장면과, 내가 클릭했을 때 반응하는 장면은 느낌이 어떻게 다른가요?

7차시

2단계: 클릭 위치를 목표로 사용하기

목표: 클릭한 위치를 바로 이동시키지 않고, “목표 위치”로 저장한 뒤 공이 천천히 따라가게 만든다. 변수의 필요성을 자연스럽게 경험한다.

target_xif위치 비교

실습 코드 6-2: 클릭한 x 위치로 천천히 이동하기
from vpython import *

scene_background(color.cyan)
label(pos=vector(0, 2.8, 0), text="클릭한 쪽으로 공이 이동합니다", height=12, color=color.black)
box(pos=vector(0, -0.1, 0), size=vector(8, 0.2, 5), color=color.green)

hero = sphere(pos=vector(-3.5, 0.45, 1.3), radius=0.25, color=color.white)
marker = sphere(pos=vector(-3.5, 0.12, 1.3), radius=0.14, color=color.red)

target_x = hero.pos.x

while True:
    rate(60)

    if scene.mouse.clicked:
        click = scene.mouse.getclick()
        target_x = click.pos.x
        marker.pos.x = target_x

    if hero.pos.x < target_x:
        hero.pos.x = hero.pos.x + 0.04
    if hero.pos.x > target_x:
        hero.pos.x = hero.pos.x - 0.04
스캐폴딩 포인트: 클릭은 “명령”이 아니라 “목표를 바꾸는 사건”으로 다룹니다. 그래서 이후 키보드와 소리도 같은 목표 변수에 자연스럽게 붙일 수 있습니다.
8차시

3단계: 키보드로 목표를 조금씩 조정하기

목표: 마우스 클릭은 큰 이동, A/D 키는 미세 조정으로 역할을 나눈다. 방향키 이름은 환경마다 다를 수 있으므로 입문 예제에서는 A/D만 사용한다.

keysdownA/D

실습 코드 6-3: 클릭 + 키보드 조작
from vpython import *

scene_background(color.cyan)
label(pos=vector(0, 2.8, 0), text="클릭: 큰 이동 · A/D: 조금씩 조정", height=10, color=color.black)
box(pos=vector(0, -0.1, 0), size=vector(8, 0.2, 5), color=color.green)

hero = sphere(pos=vector(-3.5, 0.45, 1.3), radius=0.25, color=color.white)
marker = sphere(pos=vector(-3.5, 0.12, 1.3), radius=0.14, color=color.red)

target_x = hero.pos.x

while True:
    rate(60)

    if scene.mouse.clicked:
        click = scene.mouse.getclick()
        target_x = click.pos.x

    keys = keysdown()
    if 'a' in keys:
        target_x = target_x - 0.06
    if 'd' in keys:
        target_x = target_x + 0.06

    if target_x > 3.7:
        target_x = 3.7
    if target_x < -3.7:
        target_x = -3.7

    marker.pos.x = target_x

    if hero.pos.x < target_x:
        hero.pos.x = hero.pos.x + 0.04
    if hero.pos.x > target_x:
        hero.pos.x = hero.pos.x - 0.04

4단계: 소리를 “피드백”으로 넣기

목표: 소리를 배경 장식으로 넣기보다, 클릭이 잘 입력되었다는 피드백으로 먼저 사용한다. 한 음만 넣어 소리 API를 안전하게 경험한다.

실습 코드 6-4: 클릭하면 한 음으로 알려주기

if scene.mouse.clicked:

9차시

5단계: 음표 리스트로 작은 멜로디 만들기

목표: 소리 한 음이 익숙해진 뒤 리스트와 인덱스를 사용해 클릭할 때마다 다른 음이 나게 한다. 리스트가 “여러 값을 담는 도구”라는 것을 표현 맥락에서 이해한다.

listnote_index%

실습 코드 6-5: 클릭할 때마다 다음 음 내기
# while True 위에 준비합니다.
garden_notes = ['도4', '미4', '솔4', '높은도4']
note_index = 0

# 클릭 처리 부분 안에서 사용합니다.
play_note(garden_notes[note_index], duration=0.18, type='sine', volume=0.25)
note_index = (note_index + 1) % len(garden_notes)
교사용 포인트: 오디오는 마지막에 갑자기 붙이는 장식이 아니라, “사건을 알려주는 피드백 → 감정과 리듬을 더하는 표현” 순서로 확장하면 학생이 훨씬 자연스럽게 받아들입니다.

모듈 4. 팀 프로젝트와 GitHub 기록

팀 프로젝트 운영 흐름

  1. 팀장이 VPyLab 프로젝트를 만든다.
  2. 초대 코드를 팀원에게 공유한다.
  3. 팀원은 코드를 이어받아 하나씩 기능을 추가한다.
  4. 저장할 때 “한 일, 막힌 점, 다음 할 일”을 남긴다.
  5. GitHub 저장소와 Pages 링크로 프로젝트를 공유한다.
교사용 포인트: 완성물만 보지 말고 저장 이력과 항해 일지를 함께 평가합니다. 누가 어떤 문제를 발견했고, 어떻게 해결했는지 확인할 수 있습니다.

선택 옵션: GitHub 공동 작업자 추가

GitHub 공동 작업자 추가는 필수는 아니지만, 팀원의 개발 기여와 협력 과정을 GitHub에 공식 기록으로 남기고 싶을 때 추천합니다.

공동 작업자 추가 방법

  1. VPyLab 프로젝트의 멤버 / 초대 코드 메뉴를 연다.
  2. 공동 작업자 초대 버튼을 눌러 GitHub 접근 관리 화면으로 이동한다.
  3. 또는 GitHub 저장소에서 Settings → Collaborators 또는 Manage access로 들어간다.
  4. Add people을 누르고 팀원의 GitHub 아이디나 이메일을 검색한다.
  5. Invite collaborator를 누른 뒤, 팀원이 GitHub 알림이나 이메일에서 Accept invitation을 누르면 완료된다.

공동 작업자 추가의 메리트

  • 팀원이 직접 커밋, PR, 이슈, 리뷰를 남길 수 있다.
  • 작업 내역이 팀원 본인의 GitHub 계정으로 기록된다.
  • 누가 어떤 부분에 기여했는지 명확하게 남아 협력 과정이 더 공식적으로 기록된다.
  • 이후 포트폴리오, 협업 증빙, 프로젝트 히스토리 확인에 활용하기 좋다.
주의: GitHub가 2단계 인증(2FA)을 요구하거나 초대가 아직 수락되지 않았으면 GitHub 반영이 막힐 수 있습니다. 이때도 VPyLab 저장은 먼저 남기고, GitHub 권한을 정리한 뒤 다시 저장하면 됩니다.

좋은 저장 메시지 예시

복사 가능한 저장 메시지 템플릿
제목: 클릭 이동 기능 추가
한 일: 마우스를 클릭하면 공의 목표 위치가 바뀌도록 했다.
막힌 점: 정원 밖을 클릭하면 공이 너무 멀리 갔다.
해결: x 위치를 -3.7부터 3.7 사이로 제한했다.
다음 할 일: 클릭한 위치에 소리와 색 변화를 추가하기.

모듈 5. 최종 융합 프로젝트

최종 프로젝트 조건

  • 3D 객체 5개 이상
  • 반복문 1개 이상
  • 조건문 1개 이상
  • 마우스 또는 키보드 상호작용 1개 이상
  • 소리 1개 이상
  • 저장 이력 3개 이상
  • README와 항해 일지 포함

아이디어 예시

클릭하면 별이 피어나는 밤하늘, 소리가 나는 무지개 정원, 방향키로 조종하는 우주 탐사선, 반딧불이 오르골, 날씨를 표현하는 3D 사운드 풍경

평가 루브릭

영역우수보통기초
표현3D·소리·상호작용이 아이디어와 잘 연결됨3D 장면과 일부 상호작용이 있음예제 수정 수준에 머묾
컴퓨팅 사고반복·조건·이벤트를 목적에 맞게 사용기본 문법을 일부 사용코드 의미 설명이 부족
문제 해결오류를 관찰하고 수정 과정을 기록문제를 해결했으나 기록이 부족도움 없이는 설명이 어려움
협업팀원 작업을 이어받고 기록을 남김역할 분담은 있으나 연결이 약함개인 작업 위주
기록저장 이력과 항해 일지가 과정 이해에 충분주요 저장은 남아 있음저장 메시지가 불분명

첫 수업 안내 문구

오늘 우리는 파이썬을 “외우기”보다 “써서 표현하기”로 시작합니다. 코드 한 줄이 공이 되고, 숫자 하나가 위치가 되고, 클릭 한 번이 장면을 바꿉니다. 처음부터 완벽한 코드를 쓰는 것이 목표가 아닙니다. 작게 만들고, 실행해보고, 이상한 점을 발견하고, 고치고, 그 과정을 기록하는 것이 목표입니다.
