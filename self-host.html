한 줄 결론

우리에게 가장 좋은 선택

수업 전에 빠르게 검증하려면 Vercel + Railway 또는 Render + Supabase hosted가 가장 쉽습니다.

학교나 팀에서 계속 운영하려면 단일 VPS에서 프론트와 API를 같은 도메인으로 묶고, Supabase는 hosted로 쓰는 구성이 가장 안정적입니다.

추천 구성: `https://vpylab.우리도메인.kr` → 정적 프론트 / `https://vpylab.우리도메인.kr/api` → Node API / DB와 로그인은 Supabase hosted

VPyLab 구조 이해

프론트엔드

Vite + React SPA입니다. 빌드하면 `client/dist` 정적 파일이 만들어집니다.

clientVITE_API_URL

백엔드 API

Express 서버입니다. 저장소 생성, GitHub Pages 발행, collaborator 초대 같은 API를 처리합니다.

server/api

DB / 로그인

Supabase Auth, DB, RLS, REST API를 전제로 합니다. 완전 자체 DB로 바꾸는 것은 별도 개발에 가깝습니다.

SupabaseAuth

GitHub 연동

학생/팀장의 GitHub 권한으로 저장소 생성, 커밋, Pages 활성화, 공동 작업자 초대가 진행됩니다.

public_repoPages

추천안: 단일 VPS + hosted Supabase

왜 이 구성이 좋은가?

  • 수업 중 서버가 잠들지 않습니다.
  • 프론트와 API가 같은 도메인이라 CORS 문제가 줄어듭니다.
  • 학교 도메인이나 팀 도메인으로 안내하기 쉽습니다.
  • Supabase는 hosted로 두어 로그인, DB, 보안 규칙 운영 부담을 줄입니다.
  • 나중에 Docker나 CI/CD로 고도화하기 쉽습니다.
핵심 판단: “모든 것을 우리 서버에 올리기”보다 “운영 부담이 큰 Supabase는 hosted로 두고, 앱 서버만 우리가 관리하기”가 현실적입니다.

따라 하기 절차

1단계. 저장소 포크

  1. GitHub에서 VPyLab 저장소를 fork합니다.
  2. 우리 조직이나 팀 계정 아래에 저장소를 둡니다.
  3. 로컬 서버나 작업 PC에 clone합니다.
예시 명령
git clone https://github.com/우리계정/vpylab.git
cd vpylab

2단계. Supabase 준비

  1. Supabase 프로젝트를 만듭니다. 가능하면 가까운 region을 선택합니다.
  2. 프로젝트 URL, anon public key, service role key를 기록합니다.
  3. 저장소의 Supabase migration을 적용합니다.
  4. Auth 설정에서 Site URL과 Redirect URL을 최종 도메인으로 맞춥니다.
중요: service role key는 서버 전용입니다. 프론트 코드나 GitHub Pages 문서에 절대 넣지 않습니다.

3단계. GitHub OAuth 설정

  1. Supabase Auth Provider에서 GitHub 로그인을 켭니다.
  2. GitHub OAuth App의 callback URL을 Supabase가 안내하는 URL로 설정합니다.
  3. 학생 작품을 GitHub 저장소와 Pages로 발행하려면 GitHub 권한 동의가 필요하다는 점을 수업 전에 안내합니다.
수업 운영 팁: GitHub 가입, 이메일 인증, 2FA, collaborator 초대 수락이 수업 시간을 잡아먹을 수 있습니다. 가능하면 사전 체크 시간을 따로 둡니다.

4단계. VPS에 서버 준비

  1. Ubuntu VPS를 준비합니다.
  2. Node.js, npm, nginx를 설치합니다.
  3. 방화벽에서 80/443 포트를 엽니다.
  4. 도메인의 DNS A 레코드를 VPS IP로 연결합니다.
예시 패키지 설치
sudo apt update
sudo apt install -y nginx
# Node.js는 nvm 또는 NodeSource 등 팀 표준 방식으로 설치

5단계. 프론트 빌드

프론트는 빌드 시 API 주소가 박힙니다. 같은 도메인의 `/api`로 붙일 계획이면 아래처럼 설정합니다.

client/.env.production 예시
VITE_SUPABASE_URL=https://xxxxx.supabase.co
VITE_SUPABASE_ANON_KEY=여기에_anon_public_key
VITE_API_URL=https://vpylab.우리도메인.kr
빌드
cd client
npm install
npm run build

6단계. 백엔드 환경변수 설정

server/.env 예시
PORT=10000
NODE_ENV=production
ALLOWED_ORIGINS=https://vpylab.우리도메인.kr
SUPABASE_URL=https://xxxxx.supabase.co
SUPABASE_SERVICE_ROLE_KEY=여기에_service_role_key
PUBLIC_APP_URL=https://vpylab.우리도메인.kr
보안: `SUPABASE_SERVICE_ROLE_KEY`는 서버에서만 사용합니다. GitHub에 커밋하지 않습니다.

7단계. nginx로 프론트와 API 묶기

nginx가 `client/dist`를 정적 파일로 제공하고, `/api` 요청만 Node 서버로 넘기게 합니다.

nginx 개념 예시
server {
  server_name vpylab.우리도메인.kr;

  root /var/www/vpylab/client/dist;
  index index.html;

  location /api/ {
    proxy_pass http://127.0.0.1:10000/api/;
    proxy_set_header Host $host;
    proxy_set_header X-Real-IP $remote_addr;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    proxy_set_header X-Forwarded-Proto $scheme;
  }

  location / {
    try_files $uri $uri/ /index.html;
  }
}

8단계. Node 서버 실행

수업 중 꺼지지 않도록 pm2 또는 systemd로 서버를 관리합니다.

pm2 예시
cd server
npm install
npm install -g pm2
pm2 start index.js --name vpylab-server
pm2 save

9단계. HTTPS 적용과 최종 확인

  1. Let's Encrypt 등으로 HTTPS를 적용합니다.
  2. `https://도메인/api/health`가 정상 응답하는지 확인합니다.
  3. 브라우저에서 VPyLab 접속, 로그인, 프로젝트 생성, 저장, GitHub Pages 발행까지 테스트합니다.

운영 체크리스트

도메인

  • DNS 연결
  • HTTPS 적용
  • Supabase Site URL 반영

환경변수

  • 프론트 VITE 값
  • 서버 service role key
  • ALLOWED_ORIGINS

GitHub

  • 학생 계정 준비
  • 이메일 인증
  • 2FA 가능성 안내
  • collaborator 수락 확인

수업 전 테스트

  • 로그인
  • 프로젝트 생성
  • 저장 이력
  • Pages 발행
  • 팀원 초대

주의할 점

가장 자주 막히는 부분

  • Supabase 설정: Redirect URL이 틀리면 로그인이 실패합니다.
  • CORS: 서버 `ALLOWED_ORIGINS`에 실제 프론트 도메인이 들어가야 합니다.
  • GitHub 권한: 학생이 초대를 수락하지 않았거나 권한 동의를 하지 않으면 GitHub 반영이 보류될 수 있습니다.
  • 2FA: GitHub가 2단계 인증을 요구할 수 있으므로 휴대폰 준비가 필요할 수 있습니다.
  • 서버 운영: VPS는 업데이트, 로그, 백업, 장애 대응 책임이 생깁니다.
운영 원칙: VPyLab 저장은 먼저 남기고, GitHub 반영은 권한 확인 후 이어지는 구조로 안내하면 수업 중 혼란이 줄어듭니다.
